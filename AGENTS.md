# Simple Todo, native edition

Read https://docs.expo.dev/preview/simulators/works-with/native-ios-and-android/ before changing how the app reaches Expo Simulators, and the versioned EAS docs before writing workflow YAML.

This repo is the native counterpart of https://github.com/jacobhammerle/todo-app (the Expo app). Keep `README.md` and `SETUP.md` parallel to that repo's: the same sections in the same order where the feature exists here, the native differences in the README's opening paragraphs, and a setup difference next to the step it changes in `SETUP.md`. The `scripts/tab-check-*.sh` scripts and `/tab-check` are a private demo routine; keep them out of the README.

- The app is a SwiftUI project in `ios/SimpleTodo/`: three tabs (`Views/TasksView.swift`, `DoneView.swift`, `AdminView.swift`), an in-memory store in `Model/TodoStore.swift`, and demo presets in `Model/Seed.swift`. There is no Expo SDK, no React Native, and no JavaScript; `package.json` and `app.json` are EAS tooling metadata only. Do not add them.
- `ios/SimpleTodo.xcodeproj` is generated from `ios/project.yml` with XcodeGen. Edit the spec, run `npm run xcodegen`, and commit both.
- Before you finish a change: `npm run build:simulator` must succeed, and `eas workflow:validate` must pass on every file in `.eas/workflows/` you touched. To see a UI change, run `npm run smoke -- --app build/SimpleTodo.app` (an Expo Simulator session; it bills while it runs and stops itself) or use the argent MCP server with a local simulator.
- The QA swarm (`.eas/workflows/qa-swarm.yml`) runs `scripts/agent/qa-flow.sh` per lane with the prompt in `.eas/qa-swarm-prompt.md` and the flows in `.eas/qa-flows/`. Keep the prompt's UI pitfalls and the flows in step with the screens.
- The `@expo-bot` helpers: `.github/workflows/expo-bot-bridge.yml` parses a comment and dispatches `expo-bot-verify.yml`, `expo-bot-change.yml`, `expo-bot-issue.yml`, or `pr-live-preview.yml` through `scripts/agent/dispatch.sh`. The prompts are `.eas/expo-bot-*-prompt.md`; their "Known UI pitfalls" block is the one in the QA swarm prompt, so change all of them together. The change and fix jobs run on an EAS macOS worker and gate on `npm run build:simulator`; the `fix` profile in `scripts/agent/runners/claude.sh` allows that one shell command.
- The TestFlight loop: `testflight-feedback.yml` and `testflight-crash.yml` run `scripts/agent/intake-testflight.sh` (the logic is `intake-testflight.mjs`, the triage prompt `.eas/testflight-triage-prompt.md`) and dispatch `expo-bot-issue.yml`. `release-testflight.yml` builds with the `testflight` profile and submits on every push to `main` that touches `ios/`. The submit job needs `submit.testflight.ios.ascAppId` in `eas.json`.
- Keep accessibility identifiers on controls the scripts target (`task-title-input`, `add-task`, `clear-history`, `preset-*`); `scripts/expo-simulator/smoke-test.sh` and the agent prompts depend on them. Keep that script's expectations in step with the UI text and the default seed preset.
- `scripts/write-build-info.sh` is an Xcode run-script phase that stamps build provenance into the built Info.plist. Keep the keys it writes in sync with `Support/Installation.swift`.
- Use the argent MCP server for local simulator work and the Expo MCP server (`.mcp.json`) for EAS builds, workflows, and simulator sessions. Keep the app small; it exists to be built and run by EAS.
